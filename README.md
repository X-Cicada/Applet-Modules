# Applet Modules

Applet Store 的 App 与模块发布仓库。开发工程仍在私有的 Applet-Store 仓库，本仓库只维护发布工具与分发内容。

## 下载和更新日志

打开本仓库 Releases，选择模块版本，下载附件中的 ZIP。Release 正文就是该版本的更新日志，包内 README 是具体操作说明。

机器可读目录为根目录 `catalog.json`，由发布流程自动生成，包含模块列表、最新稳定版本、历史版本、兼容条件、更新日志、下载位置、文件大小和 SHA256。私有下载需要当前账号对本仓库的读取权限。

## 发布新版本

1. 在开发工程使用既有构建器生成模块 ZIP，确认版本和相关验证。
2. 新建 Release，标签格式为 `<模块ID>-v<版本>`，例如 `xiongda-diamonds-v0.3.1`。
3. 填写本版更新说明，上传模块 ZIP，等待附件上传完成后发布。一个 Release 对应一个模块版本。
4. `Update module catalog` 自动从 ZIP 内的 module.json 读取版本、名称和兼容信息，从 Release 正文读取日志，计算文件摘要并更新 catalog.json。
5. 在 Actions 确认执行成功，再将该版本作为可用更新。发布失败时修正 Release/附件后手动运行该工作流；不会把失败当作目录更新成功。

稳定版进入目录；Draft 和 Pre-release 不进入稳定目录。旧版本保留用于查询和回退。同一版本不应替换为不同内容，修复应递增版本号。

## 使用范围

目录覆盖当前工程的全部 7 个模块：自动农场、农场观察器、百炼战斗观察、百炼游玩工具、生命周期探针、通用运行时探针、熊大快跑。探针/观察器是开发工具，安装不会自动运行。后续模块按同一流程发布。

管理器 0.13.22 接入同一目录，用于浏览模块、检查版本和 App 更新；运行中模块与本地编辑草稿仍遵守原更新约束。

自动目录工作流只使用本仓库临时 GITHUB_TOKEN，不需要新增个人访问令牌，也不访问开发仓库。ZIP 在本地构建；尚未配置从开发源码自动打包。

## 发布 App

创建标签 app-v<版本> 的 Release，上传一个 APK 和 app-release.json。描述文件包含 schema=1、packageName、version、versionCode、minSdk、size、sha256，值必须从实际 APK 提取/计算；正文为 App 更新日志。工作流验证摘要/大小后生成 catalog.app。客户端仍独立核对 APK 包名、版本和签名。
